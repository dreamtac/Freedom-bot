## 통합 중 발견하고 수정한 문제

### 알림 활성화 시 DB 이후의 과거 경기 발송

기존 구현은 DB에 저장된 경기만 기준선으로 만들었다. DB의 마지막 수집과 알림 활성화 사이에 플레이한 경기 105건이 첫 자동 갱신에서 새 경기로 분류됐다. 관리 도구가 `receipt … on`을 처리할 때 API로 현재 UID와 최신 전적을 먼저 갱신하고, 그 결과까지 기준선으로 만든 뒤 알림을 켜도록 변경했다.

오류가 발생한 두 차례 검증 DB와 WAL은 `.data/backups/integration-failed-*.sqlite*`로 보관하고, Discord에 잘못 발송된 테스트 메시지 4건은 삭제했다. 최종 검증은 최초 백업에서 다시 시작했다.

### 크레딧 총액 정합성

실제 경기에서 `PreliminaryPhase`를 포함한 출처 합계가 `totalGainVFCredit`보다 15만큼 큰 사례를 확인했다. `PreliminaryPhase`는 총 획득 밖의 초기 보유 크레딧으로 분리해 표시한다. 다른 실제 경기에서는 출처 합계와 총액 사이에 1크레딧 반올림 차이가 있어 해당 범위는 허용하고, 더 큰 초과만 정합성 오류로 유지한다.

경기 `65786713`에서는 `creditSource.GuideRobotSignature=310`과 `crUseForceCore=310`이 같은 구매를 중복 표현했다. 전용 사용 필드를 우선하고 `GuideRobot*` 값은 총 사용액의 미분류 잔액까지만 반영하도록 변경했다. 실제 세 선수의 총 사용액 310·320·330과 상세 합계를 다시 대조했으며 모두 일치했다.

첫 관찰 시 3건이 발송되고 19건은 주기당 최대 3건 제한에 따라 정상 대기했다. 이후 16건까지 순차 발송됐고, 크레딧 중복 표본도 계산 수정 후 세 번째 재시도에서 정상 발송됐다. 해당 경기에는 선수별 상세 스냅샷 3개가 저장됐고 채널·경기 중복은 계속 0건이었다.

실제 활동 화면에서 `환경 변수 1` 같은 숫자 ID가 노출된 문제를 발견했다. 기존 한글 자료의 `Installation/Name/{id}`를 연결해 이후 결과에서는 `반딧불 꽃`, `힐링 스프레이`, `하늘나리`, `폭탄열매`, `모래 질주 버섯`, `사과나무`처럼 표시하도록 수정했다.

빌드 화면에서도 경기 `65832009`의 스킬 그룹 코드가 `1003400 → 1003200`처럼 노출됐다. 캐릭터 스킬을 `T/Q/W/E/R`, 무기 스킬을 `D`로 변환하고 기존 스냅샷의 숫자 코드도 표시 시점에 보정하도록 수정했다. 같은 피오라 기록을 다시 렌더링하면 `E → Q → W → Q → Q → R → Q → W → D → Q`처럼 표시된다.

행동 화면의 코발트 전술 스킬 그룹 `500270`도 이름 조회 키가 달라 숫자로 노출됐다. 공식 그룹 자료에서 `startCode=500271`을 확인하고 언어 데이터와 연결해 `쇠약 7회`로 수정했다. 일반 모드의 구형 그룹 코드와 다른 코발트 그룹 코드 모두 처리하며, 기존 상세 스냅샷에도 표시 시점 보정을 적용한다.
