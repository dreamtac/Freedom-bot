# Freedom Bot

게임 공지와 패치노트를 감지해 Discord 서버에 알려주는 봇입니다.

## 요구 사항

- Node.js 24 LTS
- Discord 애플리케이션과 봇 토큰

## Discord 봇 만들기

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 **New Application**을 선택합니다.
2. **Bot** 페이지에서 토큰을 발급합니다. 토큰은 다시 확인하기 어려우므로 `.env`에만 보관하고 Git에는 올리지 않습니다.
3. **Installation** 페이지의 Guild Install에 `applications.commands`, `bot` 스코프를 추가합니다.
4. Bot Permissions에는 `View Channels`, `Send Messages`, `Embed Links`를 선택합니다.
5. Installation 페이지의 설치 링크로 테스트 서버에 봇을 추가합니다.
6. Discord에서 개발자 모드를 켠 뒤 테스트 서버를 우클릭해 서버 ID를 복사합니다.

현재 기능에는 Privileged Gateway Intents가 필요하지 않습니다.

설치 화면에서는 **Add to server**를 선택해야 합니다. **Add to my apps**만 선택하면 슬래시 명령어는 보이지만 봇 사용자가 서버 채널에 접근하거나 공지를 전송할 수 없습니다.

## 로컬 실행

```bash
npm install
cp .env.example .env
```

`.env`에 Discord Developer Portal에서 확인한 값을 입력합니다.

```dotenv
DISCORD_BOT_TOKEN=봇_토큰
DISCORD_CLIENT_ID=애플리케이션_ID
DISCORD_GUILD_ID=개발_서버_ID
DISCORD_NOTIFICATION_CHANNEL_ID=공지_알림을_받을_채널_ID
NEWS_POLL_INTERVAL_MS=300000
ER_ENABLED=false
ER_API_KEY=
KIS_APP_KEY=
KIS_APP_SECRET=
KIS_BASE_URL=https://openapi.koreainvestment.com:9443
KIS_WS_URL=ws://ops.koreainvestment.com:21000
```

개발 서버에 슬래시 명령어를 등록한 뒤 봇을 실행합니다.

```bash
npm run register:commands
npm run dev
```

Discord에서 `/status`를 실행해 봇이 정상적으로 응답하는지 확인할 수 있습니다.

`/엔드필드 공지`를 실행하면 공식 홈페이지의 전체 공지 목록을 10개씩 확인할 수 있습니다. 버튼으로 이전/다음 페이지를 넘길 수 있고, 특정 페이지부터 보고 싶으면 `/엔드필드 공지 페이지:2`처럼 실행합니다.

한국투자증권 Open API 앱키를 설정하면 `/시세 종목:005930`, `/시세 종목:NVDA`처럼 국내·미국 주식 현재가를 조회할 수 있습니다. 미국 주식은 티커뿐 아니라 KIS 종목 마스터의 한글명과 영문명으로도 검색·자동완성할 수 있습니다.
`/시세`는 미국 주식의 데이장·프리장·정규장·애프터장 구분과, 국내 주식의 개인·외국인·기관 수급을 함께 표시합니다. 수급은 KIS가 장 마감 뒤 제공하는 최근 확정 데이터를 사용합니다.
`/야간선물`을 실행하면 KOSPI200 KRX 야간선물의 최근월물을 자동으로 찾아 현재가, 전일 대비, 시가·고가·저가, 누적 거래량을 표시합니다.
`/시장현황`을 실행하면 KOSPI, KOSDAQ, 나스닥 종합, S&P 500의 현재값과 전일 대비를 한 번에 확인할 수 있습니다.
`/지수 지수:KOSPI`처럼 실행하면 선택한 지수의 시가·고가·저가·전일 종가를 자세히 확인할 수 있으며, 국내 지수는 상승·보합·하락 종목 수도 함께 표시합니다.
`/야간선물알림 켜기`를 실행하면 KOSPI 야간선물의 기준가격 대비 `+/-1%`부터 `+/-8%`까지 돌파를 KRX 야간장(18:00~06:00)에 실시간 감시합니다. 같은 방향의 같은 구간은 세션당 한 번만 전송합니다.
`/거래량 종목:삼성전자`, `/거래량 종목:AAPL`을 실행하면 오늘 누적 거래량이 최근 평균보다 많은지 확인할 수 있습니다.
`/뉴스 종목:삼성전자`를 실행하면 KRX/NXT 주가 흐름과 해당 종목의 최근 뉴스 제목을 함께 확인할 수 있습니다. 뉴스 제목은 변동 원인을 살피는 참고 정보이며, 원인 자체를 확정하는 정보는 아닙니다.
`/주가알림 추가 종목:삼성전자`, `/주가알림 추가 종목:TSLA`를 실행하면 `+/-3%`, `+/-5%`, `+/-8%`, `+/-10%` 돌파를 실시간으로 감시합니다. 국내는 직전 NXT 거래일 종가를 기준으로 KRX 정규장과 NXT 애프터장 체결가를 비교하고, 미국은 전일 정규장 종가를 기준으로 NASDAQ·NYSE·AMEX 체결가를 비교합니다. 직전 NXT 종가가 확인되지 않으면 오래된 가격을 대신 쓰지 않고 해당 거래일 알림을 보류합니다. 같은 방향의 같은 구간은 거래일마다 한 번만 알림 채널에 전송됩니다.

주가 알림에 등록된 종목은 시장별 마감 리포트에도 자동으로 포함됩니다. 한국 거래일에는 KRX 정규장 종료 후 KOSPI·KOSDAQ과 국내 관심 종목을, 미국 거래일에는 한국시간 오전 7시 이후 NASDAQ 종합·S&P 500, 미국 관심 종목과 함께 KOSPI 야간선물·원/달러·WTI 근월물의 최신값을 알림 채널에 한 번 전송합니다. 종목 등락률은 프리장·애프터장을 제외한 정규장 일봉 종가 기준입니다.

서버 관리 권한이 있는 사용자는 `/test-notification`을 실행해 설정된 알림 채널로 샘플 Embed가 정상 전송되는지 확인할 수 있습니다. 명령어를 추가하거나 변경한 뒤에는 `npm run register:commands`를 다시 실행해야 합니다.

봇은 시작 직후 엔드필드의 현재 공지를 확인합니다. 첫 실행에서는 기존 공지를 SQLite 데이터베이스 `.data/freedom-bot.sqlite`에 저장만 하며, 이후 처음 발견한 공지만 알림 채널에 전송합니다. 이전 JSON 저장소가 있으면 자동으로 SQLite에 이전됩니다.

Discord 연결 없이 공지 수집만 확인하려면 다음 명령어를 사용합니다.

```bash
npm run check:news
```

SQLite에 저장된 최근 공지와 알림 상태는 다음 명령어로 확인합니다.

```bash
npm run list:news
```

국내 상장 종목명 검색 데이터는 같은 SQLite 파일에 저장됩니다. 최신 종목 목록으로 갱신하려면 다음 명령어를 실행합니다.

```bash
npm run update:stocks
```

미국 상장 종목명 검색 데이터(NASDAQ·NYSE·AMEX)는 다음 명령어로 갱신합니다.

```bash
npm run update:overseas-stocks
```

봇은 시작 직후 국내·미국 종목 마스터를 동기화하고, 이후 기본 24시간마다 같은 작업을 반복합니다. 새 상장 또는 상장폐지로 검색 목록이 바뀌면 설정된 알림 채널에 추가·제외 종목명과 코드를 요약해 보냅니다. 비정상적인 대량 변화는 자동으로 거부하며, 정상 갱신 직전 DB는 `.data/backups/before-stock-master.sqlite`에 보관합니다. 갱신 주기는 `STOCK_MASTER_REFRESH_INTERVAL_MS`로 조절할 수 있습니다.

SQLite는 애플리케이션에 포함된 드라이버를 사용하므로 운영체제에 별도로 설치할 필요가 없습니다.

## 이터널 리턴 전적 조회

개발용 `.env`에 `ER_ENABLED=true`를 명시하고 이터널 리턴 개발자 포털에서 발급받은 키를 `ER_API_KEY`에 입력하면 다음 명령어를 사용할 수 있습니다. `ER_ENABLED`를 생략하거나 `false`로 설정하면 키가 있어도 이터널 리턴 모듈을 불러오지 않고 명령 등록·실행에서 제외합니다. 다른 문자열은 설정 오류로 처리합니다.

- `/이터널리턴 전적 닉네임:a1s1d1f1` — 최근 전적을 페이지당 기본 5경기로 간결하게 표시합니다. 이전·다음, 상세 보기, 시즌전적, 전적분석 버튼을 제공합니다. `개수`를 지정한 기존 사용 방식도 유지합니다.
- `/전적 닉네임:a1s1d1f1` — 위 전적 조회와 같은 기능을 제공하는 단축 명령어입니다.
- `/상세전적 닉네임:a1s1d1f1` — 최근 경기 중 하나를 선택해 장비·특성·시작/사망 지역·루트 번호를 확인합니다.
- `/시즌전적 닉네임:a1s1d1f1` — 현재 티어·RP·순위와 시즌 선호 실험체 TOP 5, 본인의 실험체별 평균 피해량을 표시합니다.
- `/전적분석 닉네임:a1s1d1f1` — 같은 시즌·모드의 최근 50경기와 이전 50경기를 전체 또는 실험체별로 비교합니다.
- `/이터널리턴 랭크 닉네임:a1s1d1f1 시즌:41` — 해당 API 시즌 ID의 스쿼드 랭크를 표시합니다. API 시즌 ID는 게임에 표시되는 시즌 번호와 다를 수 있으며, 41은 확인 당시의 예시입니다.
- `/이터널리턴 무료캐릭터 모드:일반` — 무료 캐릭터 목록을 한글 이름으로 표시합니다. 랭크 모드에서 빈 목록이 반환될 수도 있습니다.

기능을 켰지만 키가 없으면 이터널 리턴 명령어에만 설정 안내가 표시됩니다. 다른 기능은 계속 사용할 수 있습니다. 한글 이름과 공통 자료는 첫 조회 시 API 8회와 한글 파일 다운로드 1회로 불러와 SQLite에 6시간 캐시합니다. 재시작 뒤에도 유효한 캐시를 재사용하고, 만료 후 자료 해시가 같으면 테이블을 다시 받지 않습니다. 이름 조회에 실패하면 코드와 안내를 표시하고 다음 요청에서 다시 시도합니다. 경기 시각은 실행하는 컴퓨터의 시간대와 관계없이 한국시간으로 표시합니다.

추가 기능을 Discord에 반영하려면 프로젝트 폴더에서 명령어를 다시 등록하고 빌드한 뒤, 운영 중인 봇 프로세스를 재시작합니다.

```bash
npm run register:commands
npm run build
```

Discord 연결과 자동 알림을 시작하지 않고 API만 확인하려면 아래 명령어를 사용합니다. 이 진단 도구도 `ER_ENABLED=true`가 필요하며 꺼진 상태에서는 API를 호출하지 않습니다. 진단 도구는 봇과 별도 프로세스로 실행되므로, 같은 키를 사용하는 봇과 동시에 호출하지 않습니다.

```bash
npm run check:eternal-return -- a1s1d1f1
```

게임 결과 후보 필드의 실제 타입·결측·0 비율과 크레딧 출처 키를 다시 조사하려면 자동 등록 유저를 대상으로 익명 집계 보고서를 생성합니다. 원본 응답·API 키·UID는 파일에 저장하지 않습니다.

```bash
npm run audit:er-receipts -- --pages 6 --output reports/eternal-return-game-receipt-sample-audit.md
```

봇 프로세스 안의 모든 이터널 리턴 Open API 요청은 하나의 대기열을 사용하며 요청 시작 간격을 최소 1.1초로 유지합니다. 직접 검색을 최신 자동 갱신과 과거 수집보다 우선 처리하고, 같은 유저의 동시 최신 전적 요청은 한 작업을 공유합니다. 429 또는 `Retry-After`가 있는 403 응답은 전체 대기열을 멈춘 뒤 최대 네 번까지 재시도합니다. 봇 종료 시 대기 요청을 취소합니다. 한글 파일 다운로드 URL처럼 Open API 밖의 요청은 이 대기열의 대상이 아닙니다.

이 제한은 한 프로세스 안에서만 공유됩니다. `check:eternal-return`은 별도 프로세스이므로 운영 봇과 동시에 실행하면 같은 개인키 제한을 함께 조정할 수 없습니다. 운영 봇을 중지했거나 이터널 리턴 기능이 꺼진 환경에서 진단합니다.

자동 수집 대상은 로컬 관리 도구로만 변경합니다. `/전적`으로 검색한 유저는 DB에는 저장되지만 자동 등록되지 않습니다. 주기는 `ER_REFRESH_INTERVAL_MS`로 조절하며 엔드필드 공지 주기 및 알림 채널 설정과 독립적으로 작동합니다.

```bash
npm run manage:eternal-return -- add 홉빵맨
npm run manage:eternal-return -- list
npm run manage:eternal-return -- disable 홉빵맨
```

동일 닉네임 이력이 여러 UID에 있으면 `disable`에 UID를 직접 입력합니다. 관리 도구와 진단 도구는 별도 프로세스이므로 실행 중인 봇과 동시에 API를 호출하지 않습니다.

닉네임 조회 API의 `userId`는 같은 닉네임을 연속 조회해도 달라질 수 있는 불투명 토큰입니다. 봇은 이를 영구 계정 ID로 간주하지 않고, 같은 닉네임의 경기·수집 상태·시즌 프로필을 최신 토큰 아래로 자동 통합합니다. API가 영구 식별자를 제공하지 않으므로 닉네임 변경 전후 기록은 자동으로 연결하지 않습니다.

이터널 리턴 기능을 켜면 같은 SQLite 파일에 `er_` 접두사의 전용 테이블을 준비합니다. UID·닉네임 이력, 유저별 경기, 최신/과거 수집 상태, 공통 이름 자료, 시즌 프로필 캐시를 다른 기능의 테이블과 분리해 저장합니다. 경기는 UID와 경기 ID의 조합으로 중복을 막으며, 같은 경기에 참여한 서로 다른 유저의 기록은 별도로 보관합니다. 기능을 끈 환경에서는 이 저장소를 열거나 마이그레이션하지 않습니다.

`/전적`은 닉네임을 UID로 확인한 뒤 최신 경기부터 DB에 갱신하고 최대 5경기를 표시합니다. 기존 사용자에게 새 경기가 10개를 넘으면 저장된 완료 경기와 다시 만날 때까지 `next` 페이지를 이어서 읽습니다. 신규 사용자는 첫 페이지를 먼저 응답한 뒤 최근 100경기를 목표로 과거 페이지를 `backfill` 우선순위에서 수집합니다. 실패하면 완료 경계를 옮기지 않고 저장된 커서부터 재개하며, API 제공 범위가 끝나면 실제 확보한 기록만 사용합니다. 자동 수집 대상으로 등록한 유저는 봇 시작 직후와 기본 5분마다 독립적으로 갱신합니다. 자동 갱신 때마다 닉네임으로 현재 UID를 다시 확인하고, UID가 달라졌으면 자동 갱신 플래그를 새 UID로 이전합니다. 새 UID의 DB 기록이 100경기 미만이고 과거 커서가 있으면 낮은 우선순위로 100경기까지 이어서 수집합니다.

전적 화면의 버튼과 선택 메뉴는 기존 메시지를 갱신하며 명령을 실행한 사용자만 조작할 수 있습니다. 화면 세션은 마지막 조작부터 15분간 유지됩니다. 봇 재시작 또는 만료 뒤 버튼을 누르면 명령어를 다시 실행하라는 안내를 표시합니다. 아직 저장되지 않은 다음 페이지는 버튼 요청을 먼저 대기 처리한 뒤 과거 수집 커서에서 추가로 가져옵니다. 시즌 프로필 갱신이 실패했지만 이전 캐시가 있으면 갱신 실패와 캐시 사용 사실을 함께 표시합니다. [구현 TODO](reports/eternal-return-implementation-todo.md)에서 진행 상태를 확인할 수 있습니다.

새 게임을 발견했을 때 전투·팀 기여·크레딧·행동·빌드를 자동 요약하는 후속 기능은 [게임 결과 알림 TODO](reports/eternal-return-game-receipt-todo.md)에 설계와 구현 순서를 정리했습니다.

### 이터널 리턴 개발 봇 반영 순서

```bash
npm run backup:db
npm run typecheck
npm test
npm run build
npm run register:commands -- --dry-run
npm run register:commands
```

그다음 개발 봇 프로세스를 재시작하고 `/전적 닉네임:홉빵맨`에서 최근·상세·시즌전적·전적분석 화면을 확인합니다. `npm run manage:eternal-return -- list`로 자동 수집 대상을 확인하며, 중단된 100경기 수집은 DB의 과거 커서에서 다음 시작 또는 5분 주기에 재개됩니다. 진단 도구나 관리 도구가 API를 호출할 때는 같은 개인키를 쓰는 봇 프로세스와 겹치지 않게 합니다.

`애플리케이션이 응답하지 않았어요`가 표시되면 명령어 등록과 실행 중인 봇을 함께 확인합니다. 통합 프로젝트에서 `npm run register:commands`, `npm run build`를 실행한 뒤 봇을 재시작합니다. 원본 이터널리턴 프로젝트의 등록 스크립트는 통합 봇의 명령 목록과 다르므로 통합 프로젝트의 스크립트를 사용합니다.

PM2 환경에서는 `pm2 logs freedom-bot --lines 100`에서 stdout과 stderr를 함께 확인합니다. 시작 시 봇 이름, ID, 명령어 개수를 한 줄로 표시하며 정상 요청의 수신·처리 상세 로그는 남기지 않습니다. 오류 로그의 `failed`와 `stage`로 실패 단계를 확인할 수 있고, `unknown-command`는 서버에 등록된 명령과 실행 코드의 불일치입니다. API 오류, 이름 데이터 조회 실패, Discord 연결 끊김·재연결·복구 기록은 유지합니다. 다른 봇에도 `/전적`이 있다면 명령어 선택 시 봇 이름을 확인하거나 `/이터널리턴 전적`을 사용하세요.

## Windows 미니PC 실행

64비트 Windows와 Node.js 24 LTS 환경에서 프로젝트를 복사한 뒤 PowerShell에서 실행합니다.

```powershell
npm ci
Copy-Item .env.example .env
npm run register:commands
npm run build
npm start
```

Windows에는 운영용 `.env`를 별도로 설정합니다. 개발용 토큰과 `.env`를 그대로 복사하지 않습니다. `.data/freedom-bot.sqlite`에는 공지·주식·알림 이력이 저장되므로 기존 운영 DB를 유지하고 정기적으로 백업합니다. 같은 운영 봇을 두 컴퓨터에서 중복 실행하지 않습니다. 별도 앱·채널을 사용하는 개발 봇은 아래 기준으로 구분합니다.

## 개발·운영 분리

| 항목 | 개발용 | 미니PC 운영용 |
|---|---|---|
| Discord Application ID / 토큰 | 개발 앱 | 운영 앱 |
| 서버·공지 채널 | 테스트 서버·채널 | 기존 운영 서버·채널 |
| `ER_ENABLED` | `true` | `false` 또는 미설정 |
| 코드 위치 | 개발 체크아웃 | 운영 체크아웃 |
| `.env`, `.data`, `logs` | 개발 폴더 내부 | 기존 운영 폴더 내부 |

DB 경로는 각 프로젝트 폴더의 `.data/freedom-bot.sqlite`입니다. 개발과 운영의 프로젝트 폴더를 따로 두고 `.data`를 공유하거나 개발 DB로 운영 DB를 덮어쓰지 않습니다. KIS·엔드필드는 기존 설정대로 작동하며 `ER_ENABLED`는 이터널 리턴에만 적용됩니다.

### 이터널 리턴 명령을 운영에서 숨기기

1. 운영 `.env`의 앱 ID·토큰을 확인하고 `ER_ENABLED=false`로 설정합니다. 키는 없어도 됩니다.
2. 해당 **운영 폴더에서** 등록 계획을 확인합니다. 이 명령은 Discord의 앱·명령 목록을 조회하지만 변경하지 않습니다.

```bash
npm run register:commands -- --dry-run
```

3. `npm run register:commands`로 적용하고 `npm run build` 후 기존 봇 프로세스를 재시작합니다. PM2 환경은 `pm2 restart freedom-bot --update-env`를 사용하며, PM2에 별도로 저장된 환경 변수도 같은 값인지 확인합니다. 작업 스케줄러 환경은 해당 봇 작업을 중지 후 다시 시작합니다.

등록 도구와 실행 중 봇은 동일한 기능 설정을 사용합니다. 등록 도구는 토큰의 실제 앱 ID가 `DISCORD_CLIENT_ID`와 일치하는지 먼저 검사합니다. 명령을 개별 등록/갱신하므로 이 프로젝트가 등록하지 않는 다른 명령은 유지합니다. 이터널 리턴이 꺼져 있으면 해당 앱의 **전역 범위와 현재 `DISCORD_GUILD_ID` 범위**에서 `/이터널리턴`, `/전적`, `/상세전적`, `/시즌전적`, `/전적분석`만 삭제합니다. 이름이 같더라도 사용자·메시지 컨텍스트 명령은 삭제하지 않습니다.

과거에 다른 서버에도 명령을 등록했다면 그 서버 ID를 명시합니다. 해당 서버의 이터널 리턴 명령만 정리하며 주식·공지 명령을 그 서버에 새로 등록하지 않습니다.

```bash
npm run register:commands -- --dry-run --cleanup-guild=123456789012345678
npm run register:commands -- --cleanup-guild=123456789012345678
```

서버가 여러 개면 `--cleanup-guild=...`를 반복할 수 있습니다. 이 옵션은 `ER_ENABLED=false`에서만 허용합니다. 등록하지 않은 범위가 자동 정리된다고 가정하지 않습니다. 기능 설정만 바꾸고 명령 등록을 실행하지 않으면 Discord에 예전 명령이 남을 수 있습니다. 봇은 그 요청을 API 호출 없이 개인 안내로 종료합니다. 전적 버튼은 앞으로 `er:` 접두어를 사용하며 꺼진 상태에서 같은 방식으로 차단합니다.

### 운영에 반영할 코드 선택

이터널 리턴 개발은 별도 작업 브랜치에서 진행하고, 주식·엔드필드 수정은 기능별 커밋으로 나눕니다. 운영은 검증된 커밋/릴리스를 체크아웃해 빌드합니다. 미완성 코드 자체를 제외하려면 전적 브랜치를 통째로 병합하지 않고 필요한 주식·공지 커밋만 운영 브랜치에 반영합니다. 미커밋 변경은 브랜치를 바꿔도 따라갈 수 있으므로 운영 배포에 개발 작업 폴더를 그대로 사용하지 않습니다.

기능 스위치는 이터널 리턴의 로드·실행·노출을 막습니다. TypeScript 빌드는 전체 소스를 검사하므로 공통 코드나 개발 소스의 빌드 오류까지 격리하는 기능은 아닙니다. 배포 전 `npm run typecheck`, `npm test`, `npm run build`를 통과한 커밋을 사용합니다. 이미 운영 중인 앱의 명령 정리와 프로세스 재시작은 이 로컬 개발 작업과 별도로 적용합니다.

## Windows 운영 작업

24시간 운영은 Windows 작업 스케줄러에 다음 두 작업을 등록하는 방식을 권장합니다.

1. **봇 실행 작업**: 로그인 여부와 관계없이 시스템 시작 시 `powershell.exe -ExecutionPolicy Bypass -File scripts\start-windows.ps1`를 실행합니다. `시작 위치`는 프로젝트 폴더로 지정하고, 실패 시 1분 간격으로 무기한 다시 시작하도록 설정합니다. 실행 로그는 `logs` 폴더에 시작 시각별로 저장됩니다.
2. **DB 백업 작업**: 매일 한 번 프로젝트 폴더에서 `npm run backup:db`를 실행합니다. 백업은 `.data/backups`에 저장되며 30일보다 오래된 일일 백업은 자동 삭제됩니다.

작업 스케줄러에서 프로젝트 폴더를 `시작 위치`로 지정하지 않으면 `.env`와 `.data`를 찾지 못할 수 있습니다. 상태 확인은 Discord의 `/status`, DB 수동 백업은 아래 명령을 사용합니다.

```powershell
npm run backup:db
```
